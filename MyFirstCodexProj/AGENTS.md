# 專案協作指引

本文件適用於此專案根目錄及其子目錄。後續修改應遵守以下已確認的需求；使用者後續的明確指示優先。

## 專案目標與範圍

- 製作登入頁的前端 HTML 雛型，交付檔案為 `login.html`。
- 頁面須可直接以瀏覽器開啟，不需安裝套件、建置或啟動伺服器。
- 目前不串接後端、不實際驗證登入、不寄送驗證碼，也不儲存或傳送使用者輸入的資料。
- 不自行擴充註冊、忘記密碼、OTP 綁定或登入後頁面等功能。

## 檔案用途

- `需求.md`：功能需求與雛型範圍。
- `界面.md`：視覺設計與響應式排版規格。
- `login.html`：登入頁雛型，包含所需的 HTML、CSS 與少量前端互動。
- `AGENTS.md`：後續開發與協作的共同依據。

## 頁面元素與互動

- 使用者帳號輸入框：標籤為「使用者帳號」，目前不限制帳號格式。
- OTP 驗證碼輸入框：使用單一欄位，支援輸入及貼上；位數與格式待實際串接時決定。
- 主要按鈕為「登入驗證」。兩欄皆為必填，空白字元不得視為有效填寫。
- 次要按鈕為「重新傳送驗證碼」，操作前須確認帳號已填寫。
- 操作結果以畫面內的文字提示呈現，明確說明僅為雛型，不宣稱已登入或已寄送驗證碼。
- 頁面底部不顯示常駐的雛型說明文字；操作後仍以提示說明雛型結果。

## 視覺與裝置支援

- 使用繁體中文介面。
- 採簡約風格，參考 Apple 的留白、字級層次、圓角與細緻陰影。
- 以淺色為主：淺灰背景、白色卡片、深色文字與藍色主要按鈕。
- 不放置 Logo。
- 採單欄排版，電腦版以置中的登入卡片呈現，手機版依可用寬度縮放並保留側邊留白。
- 使用系統字型，不依賴外部字型、圖片或 CDN。
- 欄位須有持續可見且正確關聯的標籤；支援鍵盤操作、清楚的焦點樣式及可由輔助技術讀取的狀態訊息。
- 未明確規範的視覺細節可自由發揮，但須維持以上方向與範圍。

## 修改與驗證原則

- 維持單一 HTML 檔可獨立開啟的形式；未有新需求時，不引入框架、套件或後端服務。
- 若使用者變更功能或設計方向，同步更新受影響的需求文件與本指引，避免互相矛盾。
- 修改後依影響範圍檢查：必填欄位、空白輸入、兩個按鈕的提示、鍵盤操作及電腦／手機排版。
- 確認表單操作不會重新載入或導向頁面，也不會送出使用者資料。
- 完成回報須說明實際進行的檢查；若未用瀏覽器預覽，應明確說明，不將靜態檢查描述為瀏覽器驗證通過。
